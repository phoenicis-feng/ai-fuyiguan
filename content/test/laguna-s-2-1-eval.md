Laguna S 2.1 Free 大模型专业技术评估报告
报告日期：2026年7月26日

### 评估对象：Laguna S 2.1 Free（Poolside / poolside）

摘要
Laguna S 2.1 是由 AI 编程初创公司 Poolside 于 2026 年 7 月 21 日正式发布的开源权重大语言模型。该模型专注于智能体编程（Agentic Coding）与长时程软件工程任务，采用混合专家（MoE）架构，总参数量 118B，每 Token 仅激活 8B 参数。模型原生支持高达 104 万 Token（1,048,576）的上下文窗口，并可输出最高 131,072 Token。

本报告从模型架构设计、技术参数、基准测试表现、部署生态、成本效率、竞争格局等维度对 Laguna S 2.1 进行系统性技术评估。核心发现如下：

架构层面：Laguna S 2.1 采用 48 层 Transformer 架构，256 个路由专家加 1 个共享专家，Top-10 专家路由。注意力机制采用混合滑动窗口注意力与全局注意力，结合分组查询注意力（GQA）与逐头门控机制。模型同时提供思考（Thinking）与非思考（Non-Thinking） 两种推理模式。

性能层面：Poolside 官方自测中，Laguna S 2.1 在 Terminal-Bench 2.1 上得分 70.2%，超越总参数 1.6 万亿、激活参数 490 亿的 DeepSeek-V4-Pro-Max（64.0%）。SWE-Bench Multilingual 得分 78.5%，SWE-Bench Pro 得分 59.4%。但需注意，这些为 Poolside 自有 Agent 框架下的自测结果，非中立第三方交叉验证。

效率层面：训练仅耗时 不到 9 周，使用 4,096 张 NVIDIA H200 GPU。模型提供 BF16、FP8、INT4、NVFP4 等多格式量化权重。INT4 量化后可在单张 NVIDIA DGX Spark 或 128GB Apple Silicon Mac 上运行。OpenRouter 提示缓存可使实际支付价格比标价便宜 60%-80%。

生态层面：模型以 OpenMDW-1.1 许可证 发布，允许免费使用、修改和再分发（含商业用途）。权重已在 Hugging Face 公开。已获 OpenRouter、Baseten、Vercel AI Gateway、Ollama、llama.cpp、vLLM、SGLang、TRT-LLM 等多平台与推理引擎支持。

## 一、模型概述与发布背景

### 1.1 发布信息
Laguna S 2.1 由 Poolside 于 2026 年 7 月 21 日 正式发布。Poolside 是由 GitHub 前 CTO Jason Warner 联合创立的 AI 编程初创公司，曾在 2024 年 10 月完成 5 亿美元融资、估值达 30 亿美元。此后公司经历了一年半的"沉寂期"，专注于构建"模型工厂"——一套自动化架构实验与基于代码执行结果的强化学习训练平台。

Laguna S 2.1 是 Poolside 在三个月内发布的第三款模型——此前已于 2026 年 4 月底推出 Laguna M.1（225B）和 Laguna XS.2，7 月初推出 Laguna XS 2.1（33B-A3B）。这一密集的发布节奏反映了 Poolside 在模型研发效率上的显著提升。

### 1.2 免费策略与开源生态
Laguna S 2.1 当前处于 限时免费推理 阶段：

- 免费 API 调用：通过 OpenRouter 的 `poolside/laguna-s-2.1:free` 端点，上下文 262K
- 付费 API 调用：1M 上下文，输入 $0.20/1M tokens
- 权重开源：模型权重已在 Hugging Face 公开发布
- 开源许可证：OpenMDW-1.1（Linux 基金会支持），允许商业使用
- OpenRouter 上免费版本可能使用用户输入输出进行模型训练与改进。同时提供免费聊天界面 `chat.poolside.ai`，无需登录。

### 1.3 产品定位与战略意义
Laguna S 2.1 的产品定位可从三个层面理解：

**第一**，从“参数规模竞赛”到“参数效率竞赛”的范式转移。Poolside 明确将“紧凑性（compactness）”作为核心商业论据——模型以 8B 激活参数实现与数倍乃至数十倍规模模型匹敌的编码能力。在发布的可视化对比中，Poolside 将模型规模（总参数/激活参数）与基准得分关联展示，引导市场关注“每激活参数的智能密度”而非绝对规模。

**第二**，西方开源阵营对“中国主导开源模型市场”的战略回应。Habr 报道指出，过去一个月 OpenRouter 上最受欢迎的五款模型全部来自中国（小米、腾讯及 Z-AI 等初创公司）。西方实验室已 11 个月未发布百亿参数级别的开源模型。Laguna S 2.1 的发布被部分媒体解读为“美国试图从中国手中夺回开源主动权”的标志性事件。

**第三**，“模型工厂”工业化研发模式的验证。Poolside 宣称其平台将“原本需要数周的工作压缩至一小时”，Laguna S 2.1 的训练仅耗时不到 9 周。公司承诺后续将保持约每 5 周一次的发布节奏。

Laguna S 2.1 的核心架构特征可概括为“118B 总参数、8B 激活参数、1M 上下文、256 专家、Top-10 路由、混合注意力”。

### 2.2 MoE 专家架构
Laguna S 2.1 采用 稀疏混合专家（Sparse MoE） 架构：

- **256 个路由专家（Routed Experts）**：每个 Token 通过门控网络动态选择最相关的专家
- **1 个共享专家（Shared Expert）**：在所有 Token 上均激活，提供基础能力
- **Top-10 专家路由**：每个 Token 激活 10 个专家（256 个中的 10 个，激活率约 3.9%），加上共享专家共 11 个专家参与计算
- **激活参数**：8B/Token = 118B × 约 6.8%

这一专家配置在 MoE 模型中属于高路由密度设计。作为对比，Mixtral 8×7B 为 8 专家中选 2 个（25% 激活率），DeepSeek-V3 为 256 专家中选 8 个（3.1% 激活率）。Laguna S 2.1 的 10/256（3.9%）激活率与 DeepSeek-V3 相当，但每 Token 激活的绝对参数量（8B）显著更高，意味着每个 Token 可获得更强的专家组合表征能力。

### 2.3 混合注意力架构
Laguna S 2.1 的注意力机制设计体现了对长上下文编码任务的深度优化：

**（1）混合滑动窗口与全局注意力**

48 层中分布为：

- **12 层全局注意力（Global Attention）**：捕获长距离依赖关系
- **36 层滑动窗口注意力（Sliding-Window Attention）**：以局部窗口聚焦近邻 Token，降低计算复杂度

这种设计使模型能够在 1M 上下文中既保持对全局结构的感知，又通过滑动窗口机制控制计算成本。对于代码库级别的理解任务，全局层负责理解项目整体架构，滑动窗口层负责细粒度代码模式识别。

**（2）分组查询注意力（Grouped-Query Attention, GQA）**

GQA 通过将查询头分组共享键值头，在保持注意力质量的同时显著降低 KV Cache 的内存占用——这对于 1M 上下文窗口的推理尤为关键。

**（3）逐头门控机制（Per-Head Gating）**

每个注意力头独立配备门控单元，实现动态注意力头激活。模型可根据输入内容自适应决定哪些注意力头参与计算，进一步提升计算效率。

### 2.4 推理模式：思考（Thinking）与非思考
Laguna S 2.1 提供两种推理模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 非思考模式（Regular） | 直接生成响应，速度快、Token 消耗少 | 代码问答、聚焦编辑、快速审查、交互式工作 |
| 思考模式（Thinking） | 通过更多 Token 进行深度推理 | 仓库级变更、困难调试、终端 Agent、需持久性的任务 |

Poolside 建议不要习惯性启用思考模式，因为思考模式虽然能显著提升困难任务的表现，但 Token 消耗可能增加数倍。这一设计体现了“按需分配推理预算”的效率理念——简单任务用轻量模式，复杂任务才启用深度推理。

### 2.5 训练方法论
Laguna S 2.1 的训练过程体现了 Poolside “模型工厂”平台的核心能力：

**训练规模：**

- 开始时间：2026 年 5 月 22 日
- 训练时长：不到 9 周
- 计算资源：4,096 张 NVIDIA H200 GPU

**后训练（Post-Training）策略：**

- 在终端与软件工程环境中进行，包含真实仓库历史
- 已合并的 Pull Request、注入的 Bug、删除文件的重构
- 依赖安装与测试执行
- 使用多种 Agent 框架训练，使行为可跨不同编码 Agent 迁移

**训练透明度：** Poolside 发布了所有基准测试的完整运行轨迹（Trajectories）——包括工具调用序列、推理过程、代码变更与验证结果。这在行业普遍保密的背景下极为罕见，被部分评论者视为“近乎挑衅”的透明度宣言。

一个具体案例：Poolside 展示了 Laguna S 2.1 自主证明 Erdős 第 397 号问题（一个组合数学难题）的完整轨迹——这一任务此前仅最前沿的旗舰模型能够完成。

另一个工程化案例：Laguna S 2.1 在数小时内优化了 Poolside 自己的 Agent 框架，最终实现 5.2% 的速度提升和约 70% 的内存分配降低。

## 三、性能评估

### 3.1 官方基准测试结果
Poolside 官方使用自有 Agent 框架（Harbor Framework）在思考模式开启下进行了基准测试。结果如下：

| 基准测试 | Laguna S 2.1 得分 | 测试内容 |
|---|---|---|
| Terminal-Bench 2.1 | 70.2% | 通过终端完成实践任务 |
| SWE-Bench Multilingual | 78.5% | 跨编程语言的软件问题修复 |
| SWE-Bench Pro | 59.4% | 现有代码库中的困难问题求解 |
| DeepSWE v1.1 | 40.4% | 长时程软件工程任务 |
| SWE Atlas | 46.2% | 代码库问答 |
| Toolathlon Verified | 49.7% | 多种工具的正确使用 |

**Terminal-Bench 2.1（70.2%）** 是 Poolside 最突出的宣传点：

- 超越 DeepSeek-V4-Pro-Max（总参数 1.6 万亿、激活参数 490 亿）的 64.0%
- 超越 NVIDIA Nemotron 3 Ultra 和 Thinking Machines Inkling
- 在 Poolside 的对比表中排名高于 Inkling 和 DeepSeek V4 Pro Max

**SWE-Bench Multilingual（78.5%）**：

- 与 Qwen 3.7 Max 的 78.3% 基本持平
- 但需注意的重要限制：
  - 非中立第三方验证：这些为 Poolside 自有 Agent 框架下的自测结果
  - 非同一环境重测：对比模型的分数来自其各自公开报告，非同一测试环境
  - 模型尚新：独立第三方测试仍然有限

## 五、竞争分析与行业定位

### 5.1 核心竞争优势
1. 极致的参数效率

以 118B 总参数、8B 激活参数，在 Terminal-Bench 2.1 上超越 1.6T 总参数的 DeepSeek-V4-Pro-Max。“智能密度”（每激活参数单位智能）指标上具有显著优势。

2. 超长上下文处理能力

原生 1,048,576 Token（104 万）上下文窗口，可容纳整个中等规模代码库。混合滑动窗口与全局注意力的架构设计，使模型在长上下文中仍能保持合理计算效率。

3. 双模式推理的灵活性

思考/非思考双模式让开发者可根据任务复杂度按需分配推理预算——简单任务用快速非思考模式，复杂任务启用深度思考模式。

4. 完整的开源生态覆盖

从 BF16 原始权重到 INT4/NVFP4 量化，从 GGUF 到 MLX，从 vLLM 到 llama.cpp——几乎覆盖了所有主流推理框架和部署场景。

5. 训练透明度与可复现性

发布所有基准测试的完整运行轨迹，在行业内极为罕见，为学术研究和结果验证提供了宝贵资源。

6. “模型工厂”的持续迭代能力

训练仅耗时不到 9 周，公司承诺约 每 5 周发布一次 新模型——这意味着 Laguna 系列将以高频节奏持续进化。

### 5.2 核心劣势与风险
1. 基准测试与真实性能的落差

社区反馈显示“基准测试未能转化为实际性能表现”。多个用户观察到模型存在 “虚构问题”（confab issue） ——即在不确定时倾向于生成看似合理但实际错误的输出。

2. 与顶级模型的显著差距

Terminal-Bench 2.1 排名第 11 位（22 个模型中）。与 Kimi K3 等前沿模型相比，DeepSWE 从 69.0% 到 40.4% 的差距高达 28.6 个百分点。

3. 推理速度偏慢

社区实测约 10 token/s，在实时交互场景中可能影响体验。

4. 独立第三方验证缺失

目前所有亮眼数据均来自 Poolside 自有 Agent 框架下的自测。独立第三方的大规模系统评测尚未完成。

5. 免费版本的数据使用政策

免费 API 版本可能使用用户输入输出进行模型训练与改进——对处理敏感代码或数据的用户构成隐私顾虑。

### 5.3 行业定位总结
Laguna S 2.1 的行业定位可概括为：

“一款以极致参数效率为核心竞争力的开源编码 MoE 模型，在 Terminal-Bench 等 Agent 编码基准上表现优异，以 118B 总参数/8B 激活参数的规模实现了与数倍规模模型匹敌的编码能力。其超长上下文（1M）、双模式推理和完整的开源生态覆盖，使其成为本地 Agent 编码场景的有力选择。但与 Kimi K3 等前沿模型在复杂软件工程任务上仍存在显著差距，且官方基准数据尚需独立第三方验证。”

### 6.3 场景选择决策框架
何时使用 Laguna S 2.1：

- 需要在本地处理百万 Token 级代码库

- 任务为 Terminal/Agent 类 编码任务

## 七、总结与展望

### 7.1 技术贡献评估
Laguna S 2.1 在大模型技术演进中做出了以下贡献：

1. 验证了“小激活、大容量”MoE 架构在编码领域的可行性

以 8B 激活参数在 Terminal-Bench 2.1 上超越 490B 激活参数的 DeepSeek-V4-Pro-Max，证明通过精细的 MoE 架构设计（256 专家、Top-10 路由、混合注意力），可在极低推理成本下获得顶级编码能力。

2. 混合注意力架构在超长上下文场景的工程化验证

12 层全局注意力 + 36 层滑动窗口注意力的混合设计，在 1M 上下文窗口下实现了计算效率与表征能力的平衡，为长上下文 MoE 模型的设计提供了可参考的范式。

3. “模型工厂”工业化研发模式的验证

不到 9 周、4,096 张 H200 的训练，加上约每 5 周的发布节奏承诺，表明大模型训练正从“手工打造”走向“工业化流水线”。

4. 训练透明度的行业标杆

发布所有基准测试的完整运行轨迹，在行业普遍保密的背景下树立了可复现性、可验证性的新标准。

5. 开源生态的全面覆盖

从 BF16 到 INT4/NVFP4，从 vLLM 到 llama.cpp 的全栈推理框架支持，为开源模型的“开箱即用”设立了新标杆。

### 7.2 待验证与待改进方向
1. 独立第三方验证

官方宣称的 Terminal-Bench 2.1 70.2% 等数据尚需中立第三方大规模验证。

2. 真实世界性能与基准的差距

社区反馈的“基准测试不转化为实际性能”问题需要正视和解决。

3. 推理速度提升

~10 token/s 的速度在实时场景中偏慢，需进一步优化。

4. “虚构问题”的抑制

多个用户观察到的 confab issue需要从训练或后训练层面加以解决。

5. DeepSWE 等复杂任务能力的提升

40.4% 的 DeepSWE 得分与 Kimi K3 的 69.0% 差距显著，长时程软件工程任务能力是下一版本的关键改进方向。

### 7.3 最终评价
Laguna S 2.1 是一款在设计理念和执行层面均具有鲜明特色的开源编码模型。它以“参数效率优先、开源生态全覆盖”为核心设计哲学，在 Terminal-Bench 等 Agent 编码基准上展现了与数倍规模模型匹敌的能力，在超长上下文（1M）、双模式推理和部署生态覆盖方面达到了行业领先水平。

模型的真正价值可能不在于“击败”某个特定竞品，而在于为开源编码模型树立了一个新的效率标杆——证明通过精细的 MoE 架构设计（256 专家、Top-10 路由、混合注意力）和系统化的后训练（终端环境、真实仓库历史、多 Agent 框架），可以在极低的推理成本下获得高质量的 Agent 编码能力。

对于开发者而言，Laguna S 2.1 是本地 Agent 编码、仓库级代码理解、终端自动化场景的理想选择，尤其适合需要在本地处理百万 Token 级代码库且预算有限的场景。对于开源社区而言，其 OpenMDW-1.1 许可证和全栈推理框架支持为社区生态的繁荣奠定了基础。对于整个 AI 行业而言，其“模型工厂”的工业化研发模式和训练透明度承诺，为后训练时代的模型开发提供了值得关注的新范式。

但必须清醒认识到：官方基准数据尚需独立第三方验证，模型在真实世界任务中的表现与基准存在差距，推理速度偏慢，且与 Kimi K3 等前沿模型在复杂软件工程任务上仍有显著差距。建议开发者在生产环境部署前进行充分的本地评估和压力测试。
